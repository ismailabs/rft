# Codex autonomous execution contract — explicit scope

This is an instruction for **future Codex work after the handoff is installed**. It does not authorize handoff-preparation ChatGPT to modify the repository or providers.

## Permitted within RFT scope
Inspect local Git/repository and approved provider metadata; read `.agents/skills/` and `assets/`; choose and install suitable **free** dependencies; write/refactor app, migrations and tests; create optimized derivatives (preserve originals); use synthetic isolated dev/test data; run builds/tests/CI; repair recoverable issues; create feature branches, commit, push and open PRs; create safe preview deployments; conditionally production deploy once **every evidence-backed gate** passes.

## Not permitted
Spend money; enable billing or paid extensions; touch unrelated repositories or accounts; expose secrets, real financial histories or credentials; delete source assets/skills without verified reason; force-push/reset/discard uncommitted work; silently bypass MFA/RLS/tests; use privileged credentials on client; execute destructive production data migration, delete real customer records or disable production security to proceed; silently change scope to bank integration, financial AI or extra auth providers; claim completed work without verification.

## Autonomous decision-making
Codex may decide normal engineering details that respect the approved architecture and documented constraints. Record significant choices, rationales and measured tests. If an actual technical collision arises, implement safe reversible work and report the blocked decision. Do not ask the nonexpert for routine API/library choices.

## Production release rule
Automated first production launch is **preauthorized only if** required security, financial, UX/accessibility, OAuth, privacy, recovery, budget/provider eligibility and other checks pass, and no prohibited irreversible action is required. A checklist auto-filled by Codex is insufficient without actual evidence. A failed or skipped mandatory check blocks production. Do not circumvent review requirements imposed by external providers.

## Work in sessions, not fictional uninterrupted background operation
Continue through authorized stages while tools/session allow; maintain progress and recovery notes for interruptions. Never claim ongoing work when the process has stopped. At every resumed session, verify branch state, pending changes and last validated phase.

## Blocker response shape
`Where blocked | exact technical finding | what safe work completed | user impact | specific required human action (click steps) | confidential information to protect | resumption point`. Do not ask user to reveal raw secrets in conversation.
